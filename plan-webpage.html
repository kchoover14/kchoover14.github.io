Site Structure

The portfolio is a Quarto website with four pages:

  • Landing page (index.qmd) — bio, skills cards, links
  • About Me (about.qmd) — full bio and publications list
  • Scientific Research (scientific-research.qmd) — eggplant theme, 8 project cards
  • Applied & Policy Research (applied-policy.qmd) — blues theme, 14 project cards

Navigation

  • Navbar: About Me | Scientific Research | Applied & Policy Research | GitHub icon (right)
  • Site name/brand (“Kara C. Hoover”) in navbar links home — no separate Home tab
  • QMD source files are local-only and never committed to git. Only _site/ is pushed.

Render & Deploy Workflow

  1. Make edits to QMD and SCSS files locally
  2. Delete _site/ folder
  3. Run quarto render
  4. Push _site/ to GitHub
  5. No YAML changes needed when swapping style-master.scss — filename stays the same

Theming

Two palettes controlled by style-master.scss

Blues (default / Applied & Policy pages) - Primary: #004080 - Used in: applied-policy.qmd - Body class: blues (default, no class needed)

Eggplant (Scientific Research / academic pages) - Primary: #6b3d72 - Primary dark: #532f5a - Used in: scientific-research.qmd and all individual project pages (smelling-in-the-wild, subsistence-impacts-occipital-biomechanics, peripheral-resilience-ryukyu-colonialism) - Body class: add body-classes: eggplant to QMD YAML

TOC active link color (eggplant pages): #45733E (forest green)

Landing page uses fern green (#6b8f71) — separate inline styles in index.qmd, not controlled by style-master.scss.

Applying the theme to a project page

Each project repo needs its own style-master.scss (copy from portfolio root). No _quarto.yml changes needed — the SCSS filename is the same everywhere.

Card Rules

Scientific Research cards (eggplant)

Every card must have exactly three pills: 1. DOI — links to the published article 2. Project page — links to the GitHub Pages portfolio page (https://kchoover14.github.io/repo-name/) 3. Repository — links to the GitHub repo (https://github.com/kchoover14/repo-name)

Cards without a project page yet still show the DOI and Repository pills. The Project page pill is added when the page is built. Cards already have a page but are missing DOI — this needs to be fixed (see Backlog).

Description rules: - Card description and GitHub repo description must match exactly — card is the master - For published projects: description is findings-forward (states the result, not just the question) - For unpublished or unreviewed projects: use a minimalist question-focused description (Ryukyu-style: describe the question/approach, not the finding) - For repos where scripts are being updated but no new analysis is being done: use the formula “Scripts and data for [publication title or topic].” — neutral, accurate, doesn’t overclaim - Journal name and year appear in italics at the end of the description for published work - Card and repo descriptions must mirror exactly — when in doubt, update the repo to match the card

Applied & Policy Research cards (blues)

Each card has two pills: 1. Project page — links to the GitHub Pages portfolio page 2. Repository — links to the GitHub repo

No DOI pills on blues cards (these are applied/data science projects, not journal publications).

Pill label conventions

  • DOI link: label is DOI
  • Portfolio page link: label is Portfolio page
  • GitHub repo link: label is GitHub repo

Description Conventions

Situation Approach
Published, findings confirmed Findings-forward: state the result
Published, findings not confirmed/reviewed Question-forward: state the question and approach (Ryukyu model)
Unpublished, in progress Question-forward with no journal citation
Scripts being updated, no new analysis “Scripts and data for [topic/title].”
Placeholder (page not yet built) Minimalist — do not invent findings

Git Rules (Lessons Learned)

  • Never run git clean -fd — QMD source files are untracked by design and will be permanently deleted
  • Never run git reset --hard — same risk
  • Read-only diagnostics only: git status, git log, git diff
  • To force-stage a file Git thinks is unchanged: git add -f filename
  • Recovery of deleted untracked files: only possible from rendered HTML in _site/ — painful and imperfect
  • If Git pane shows phantom files (??): investigate with git status before taking any action
